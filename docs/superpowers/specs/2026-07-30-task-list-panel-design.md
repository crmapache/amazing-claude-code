# Список задач: закреплённая read-only панель вместо карточки в ленте

## Контекст и цель

Сейчас список задач (`TodoWrite`) — обычная карточка ленты (`TodoCard`,
тип элемента `todo` в `FeedItem`). У неё три проблемы:

1. Она едет вместе с остальной лентой и уходит из виду, стоит агенту
   сделать ещё пару шагов — хотя это единственная карточка, которая должна
   быть на виду постоянно, пока работа идёт.
2. Строки списка кликабельны (`onToggle` снимает/ставит галочку локально,
   через `useCardState.todoOverrides`) — остаток от теста; пользователь не
   должен иметь возможность самому отмечать чужие задачи.
3. Список ничем не ограничен по высоте: длинный план разрастается на пол-
   экрана.

Цель: превратить список задач в закреплённую, только читаемую панель над
полем ввода — по образцу уже существующих `Queue`/`Quotes`
(`webview/src/components/`), с ограничением высоты и раскрытием по клику.

## Данные: откуда панель берёт текущий список

Каждый вызов `TodoWrite` по-прежнему добавляет новый элемент `kind: 'todo'`
в общую историю событий (`build.ts` не меняется) — это единственный
источник истины про список задач, терять его не нужно. Меняется только то,
кто и как его показывает.

Добавляется чистая функция-селектор (например, в `feed/types.ts` рядом с
`TodoItem`, либо в самой панели — на усмотрение реализации):

```ts
const latestTodo = (items: FeedItem[]): TodoItem | undefined =>
  [...items].reverse().find((item): item is TodoItem => item.kind === 'todo')
```

`App.tsx` вызывает её от `panel.items` и передаёт результат в новую панель.

## Лента больше не показывает карточку списка

`Feed.tsx` перестаёт рендерить `todo` как обычную карточку: элементы с
`kind: 'todo'` отфильтровываются из `items` перед `.map` на рендер строк.
Чтобы `switch` в `ItemView` остался исчерпывающим без мёртвой ветки
`case 'todo': return null`, тип пропа сужается через
`Exclude<FeedItem, TodoItem>` (или эквивалентный самодельный type guard) —
после фильтрации `'todo'` физически не входит в возможные `kind`.

## Новая панель `TaskListPanel`

Новый файл `webview/src/components/TaskListPanel.tsx` — рядом с `Queue.tsx`
и `Quotes.tsx`, тем же паттерном (принимает данные, сам решает
показываться ли, возвращает `null` когда нечего показывать).

**Расположение.** Рендерится в `App.tsx` внутри `composer.dock`, самым
первым — перед `Queue`, перед `Quotes`, сразу под границей, отделяющей
ленту от зоны ввода. Ширина — на всю ширину дока, как у соседей.

**Только просмотр.** Пропа `onToggle` не будет вовсе. Строка списка — `div`,
не `button`: без ховера, без курсора-руки. Чекбокс остаётся визуальным
индикатором состояния (✓ / текущая / ожидает), не контролом.

**Приоритизация и схлопывание.** Показываем не больше 5 строк. Если задач
больше:

```ts
const LIMIT = 5

function pickVisible(todos: TodoEntry[]) {
  if (todos.length <= LIMIT) return { visible: todos, hidden: [] }

  const notDone = todos.filter((t) => t.state !== 'done')
  const done = todos.filter((t) => t.state === 'done')

  const shown = new Set([...notDone, ...done].slice(0, LIMIT).map((t) => t.id))
  return {
    visible: todos.filter((t) => shown.has(t.id)),
    hidden: todos.filter((t) => !shown.has(t.id)),
  }
}
```

Сначала забираем невыполненные (текущую и ожидающие), затем, если слоты
остались, — выполненные. Но сама видимая пятёрка рендерится в исходном
порядке списка (фильтр по `shown`, не пересортировка) — читается как
обычный чек-лист, а не как перетасованный.

**Раскрытие.** Под видимыми строками — строка-кнопка:

- свёрнуто: `▾ +{hidden.length} more · {hidden.filter(t => t.state === 'done').length} done`
- по клику — раскрывает весь список, кнопка меняется на `▴ Show less`

Состояние раскрытия — локальный `useState<boolean>` внутри компонента,
никуда не сохраняется и не шлётся агенту. Если после раскрытия список
длинный (десятки пунктов), контейнер получает `max-height` с внутренним
скроллом, чтобы не выталкивать поле ввода за экран.

**Автоскрытие.** Если в последнем списке все задачи `done` — панель
возвращает `null` целиком (как `Queue` при пустой очереди). Появится снова
только когда придёт новый `TodoWrite`.

## Сопутствующая правка: мёртвый код

С удалением интерактивности становятся не нужны:

- `TodoCard.tsx` (`webview/src/components/items/`) — переезжает/переписывается
  в `TaskListPanel.tsx`, старый файл удаляется.
- В `useCardState.ts`: `todoOverrides`, `setTodo` и их поля в `CardState`.
- `todoOverridesFor` в том же файле.
- Соответствующая проводка в `Feed.tsx` (`case 'todo'` с `overrides`/`onToggle`).

## Границы (что не трогаем)

- Формат данных `TodoItem`/`TodoEntry`/`TodoState` и логика `build.ts` для
  `TodoWrite` — без изменений.
- Остальные карточки дока (`Queue`, `Quotes`, `Composer`) — без изменений,
  кроме порядка (панель встаёт перед ними).
- Прогресс-счётчик в шапке панели (`N / M done`) считается по полному
  списку, не по видимой пятёрке — как и сейчас.

## Проверка

- В сценарии харнесса «Список задач» (`webview/src/harness/scenarios/cards.ts`,
  сценарий `todo-list`) сейчас всего 3 пункта — недостаточно, чтобы увидеть
  схлопывание. Расширить список до 6+ пунктов (или добавить отдельный
  чекпоинт с обновлённым `TodoWrite`), чтобы обе формы — свёрнутая и
  развёрнутая — были видны и проверяемы глазами.
- `tsc --noEmit` и `vitest run` в `webview/`.
- Визуальная проверка в браузере (`pnpm dev` + харнесс): панель прибита
  над полем ввода, не кликается, схлопывается/разворачивается, исчезает
  при 100% выполнении и появляется заново на следующем `TodoWrite`.
