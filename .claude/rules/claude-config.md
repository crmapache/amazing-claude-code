## Настройки Claude Code: экран, который открывает `/config`

Пришло отзывом: в терминале `/config` открывает экран с вкладками, где настройки меняются на месте, а в
панели выдавал простыню. Панель гоняет CLI потоком, и там та же команда печатает справку - `Usage: /config
key=value` и под ней около сорока строк `ключ=вариант|вариант`. Что `/config ключ=значение` в этом режиме
работает, видно не было, и человек правил файлы руками.

Теперь `/config` без аргументов - команда панели (`panelCommands` в `catalog.ts`, правило в `localCommand`):
открывает экран «Claude Code settings» в настройках бокового меню. С `ключ=значение` - уходит в CLI как
набрано: он делает ровно то, что попросили.

### Что чьё

- **Список настроек и их вариантов - от CLI** (`ClaudeConfig.parse`): одна и та же справка, разовый запуск
  `claude -p --no-session-persistence` с `/config` на stdin. Модель не зовётся, разговор в историю не
  ложится (замерено), около трёх секунд в проекте с MCP. Кэш на исполняемый файл и его дату
  (`ClaudeConfigDesk.catalog`): новая версия CLI - новый список. Настройка, которую знает только новый CLI,
  появляется сама, в группе «Other» и под своим ключом.
- **Запись - тоже CLI** (`ClaudeConfig.command` → `/config ключ=значение`): его писатель, его файлы, его
  проверки и отказы. Только ключ из списка и только значение из его вариантов (или любое одной строкой для
  `<value>`): команда уходит в процесс на этой машине. Через stdin, а не аргументом - значение языка бывает
  с пробелами, и правило про аргументы в CLAUDE.md никто не отменял.
- **Текущее значение CLI в этом режиме не говорит**, поэтому читается из его файлов по его же правилам
  (`ClaudeConfig.SPECS`, снято со сборщика экрана `l$e` и умолчаний `Be()` в 2.1.280): «глобальные» -
  `settings.json` пользователя, потом старый `~/.claude.json` (`ClaudeHome.globalConfigFile` - сосед
  `~/.claude`, а при `CLAUDE_CONFIG_DIR` внутри него), потом умолчание CLI; обычные - по слоям проекта
  сильнейший первым (`ClaudeSettings.sources`).
- **Умолчание не угадывается.** Где CLI считает его на ходу (флаги, тариф) - `default = null`, и экран не
  отмечает ни один вариант, а пишет «Not set - Claude Code decides». Переключатель, показывающий «вкл» у
  выключенной настройки, хуже, чем никакого.
- **Куда пишет `/config`, у каждой настройки своё** (сборщик экрана CLI, 2.1.280): `R(...)` - в
  `settings.json` пользователя, `B("...")` - глобальная, тоже в `settings.json` пользователя (замерено),
  `H(...)` - в старый `~/.claude.json`, `be(...)` - **в `.claude/settings.local.json` текущего проекта**.
  Последних четыре: `tips`, `reduceMotion`, `outputStyle`, `defaultView` (замерено живьём: `tips=true` лёг
  в локальный файл песочницы, а не в `~/.claude`). Они действуют только в этом проекте, и ряд говорит это
  прямо (`projectOnly`) - иначе переключатель в соседнем проекте «не работает».
- **Перебитое проектом не притворяется изменяемым** (`lockedBy`): если слой сильнее того, куда пишет
  `/config`, держит настройку, ряд неактивен и говорит, где задано.
- **Порядок - по важности** (порядок `SPECS`), а не по алфавиту ключей, как печатает CLI; незнакомые - в
  конце, в порядке CLI.

### Поведение экрана

- Одно изменение за раз, и в IDE (`changing`), и в панели (`claudeConfigPending`): каждое - целый CLI,
  переписывающий файл, и два сразу записали бы файл каждый со своего чтения.
- Переключатель отвечает нажатию сразу, но на экране остаётся не догадка, а ответ IDE: файлы перечитываются
  после записи, и исход решается по файлу, а не по фразе CLI - настройка, прочитанная как просили, принята;
  иначе под рядом его собственные слова (`outcome`).
- Исход читается только для ключа, который ждёт эта страница: хаб отдаёт последнее сообщение каждого типа
  подключившейся позже странице, и старый отказ не должен всплыть под рядом, который никто не трогал.
- Открытые разговоры новое значение подхватывают сами: CLI следит за своими файлами настроек
  (`settingsChangeDetector` в его коде).
- **Группы**: «How Claude works» - что меняет работу разговоров и в панели; «Terminal only» - то, что рисует
  только терминал. `model` и `permissionMode` там же, с пометкой: в панели их решают чипы MODEL и MODE.
- Аккаунт не передаётся: настройки лежат в общей папке CLI, как у `claude mcp` и `claude plugin`.
- С телефона закрыто (`askClaudeConfig`, `setClaudeConfig` в `RemoteCommands.DENIED`): машинные настройки CLI,
  и для терминала тоже.
- Проверить без IDE: харнесс, `/config` в поле или «Settings» → «Claude Code settings»; плеер отвечает
  списком со всеми видами строк и отказывает стилю «Learning», чтобы было видно отказ.
