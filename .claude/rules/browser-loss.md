## Белая панель: браузер IDE останавливается сам, страница панели умирает отдельно

Отзыв в Marketplace 2026-10-29: «иногда окно становится полностью белым, помогает только перезапуск IDE».
Причин две, и до правки 2026-10-30 обе выглядели одинаково - белый прямоугольник без единого слова,
потому что плагин не замечал ни одну.

### Браузер IDE гасит сама IDE (JBR-10027)

С 2025.1 встроенный браузер живёт вне процесса IDE: один `cef_server` на всю IDE рисует все её страницы,
IDE говорит с ним по сокетам. Для обратных вызовов от сервера у IDE пул потоков (3 основных, до 10, простой
60 с), и обёртка потока при ЛЮБОМ его завершении зовёт «клиент отключился». Лишний поток, простоявший
минуту без дела, гасит весь сервер: умирают наша панель, предпросмотр Markdown и всё остальное. В idea.log
ни строчки, платформа продолжает считать браузер живым, перезапустить его можно только во внутреннем
режиме. Тикет https://youtrack.jetbrains.com/issue/JBR-10027 открыт на 2026.2. Тот же код в байткоде
WebStorm 262.8665 (песочница, там же воспроизведено) и 262.10968 (рабочая IDE).

- **Воспроизводится за минуту и только в песочнице.** Порт обратных вызовов песочницы - тот, на который у
  её `cef_server` три соединения (`lsof -p <cef_server> -iTCP -sTCP:ESTABLISHED`), не 63343 (это
  встроенный веб-сервер IDE). Открыть к нему одно соединение и закрыть, в JVM появится
  `CefHandlers-execution-3` (`jcmd <pid> Thread.print`), через 60 с сервер уходит. **На рабочей IDE так
  нельзя** (её порт 30001): погаснет панель, в которой идёт разговор.
- **Что именно у людей открывает лишнее соединение, не найдено.** Шрифты по диапазонам, перезагрузка
  страницы, инструменты разработчика, предпросмотр Markdown, пачка из 600 сообщений страницы и ход агента
  в песочнице четвёртого потока не дали (2026-10-30).
- **Единственный сигнал - слот `CefApp.setDisconnectionCallback`** (`BrowserLoss`). Платформа его не
  занимает (проверено по всем jar 2026.2), мы ставим его один раз на процесс при первом браузере. Слот
  один: если его потом займёт другой плагин, мы ослепнем. Вызывается только когда IDE не закрывается.
- **Каждая открытая панель меняет браузер на заглушку** со словами, кнопкой перезапуска IDE и ссылкой на
  тикет. Панель, открытая после этого (другой проект), браузер не строит вовсе: строить его не в чем. С
  остановленным браузером `send` и перерисовка молчат - это вызовы в закрытый сокет.
- **Обратного пути нет.** Новый `JBCefBrowser` на мёртвом сервере не создать, а перезапуск JCEF закрыт
  для обычного режима. Обходной путь для человека - `ide.browser.jcef.out-of-process.enabled=false`
  (ключ реестра; Help | Edit Custom Properties или Find Action → Registry). Панель в этом режиме оконная, а
  не offscreen; проверено 2026-10-30 в песочнице: рисуется, ход агента проходит, упавшая страница
  возвращается. Курсор, перетаскивание файлов и всплывающие окна IDE поверх панели не проверялись. В
  песочнице ключ ставится строкой в `config/options/ide.general.xml` (компонент Registry) при закрытой IDE.

### Умер процесс страницы, а браузер жив

Нехватка памяти, убийство системой, падение отрисовки. Раньше страницу никто не загружал заново.
Теперь `onRenderProcessTerminated` в `WebviewHost` перезагружает её через полсекунды (не прямо в
колбэке: Electron падал ровно на этом). Разговоры живут в IDE, свежая страница получает их на `ready`,
как после перезагрузки с экрана падения. Возврат за 1-2 секунды.

- **Не больше трёх раз за пять минут** (`PageCrashes`, с тестом). Дальше заглушка с кнопкой «Build the
  panel again», которая строит НОВЫЙ браузер (`ClaudePanel.rebuildWebview`). Старый обратно не ставится:
  вынутый из дерева браузер встаёт пустым прямоугольником. Счёт принадлежит одному браузеру и с новым
  начинается заново.
- Всё, что панель вешает на браузер (перетаскивание файлов, клавиши панели, ожидание первого слова), живёт
  под его собственным сроком (`hostDisposable`), а не под сроком панели - иначе перестройка оставляла бы
  слушателей на мёртвом компоненте.
- Проверить: в песочнице с `-PjcefDebugPort=5176` послать странице панели CDP `Page.crash`; четвёртый раз
  подряд даёт заглушку. Кнопку жать через доступность (`AXPress` по `description`), без мыши.

### Сообщения страницы обрабатываются не на потоке браузера

Браузер передаёт сообщение страницы, вызывая IDE и дожидаясь ответа. Раньше вся обработка шла прямо в
этом вызове: в idea.log процесс агента создавался внутри колбэка браузера, а чтение страницы истории из
транскрипта в десятки мегабайт держало его столько же. Теперь колбэк только кладёт сообщение в очередь
(`inbox`, один поток пула, порядок сохраняется) и сразу отпускает браузер. Сообщение, оставшееся в очереди
при закрытии панели, пропускается (`WebviewLifetime.isAlive`).
