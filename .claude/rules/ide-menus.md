## Пункты в контекстных меню IDE: редактор и дерево проекта

- **Редактор** (`EditorPopupMenu`), первыми: «Send to Amazing Claude Code GUI» - ссылка на выделенные строки или
  строку с кареткой (`SendSelectionAction`), под ним «Send Absolute Path…» - весь файл полным путём
  (`SendAbsolutePathAction`).
- **Дерево проекта** (`ProjectViewPopupMenu`) и **список изменений в окне Commit** (`ChangesViewPopupMenu`): один
  пункт «Send to Amazing Claude Code GUI» - это то же действие `SendAbsolutePathAction`, подписанное по-другому
  через `override-text` для мест `ProjectViewPopup` и `ChangesViewPopup`. Выбранные файлы и папки уходят чипами
  полным путём, мультивыбор целиком; удалённый файл в списке изменений выпадает сам - на диске его нет. Дерево
  пришло идеей пользователя (Windows, PyCharm): перетаскивание было и раньше, но в меню ищут первым делом. Окно
  Commit попросил Макс.

Решения Макса, которые не надо переигрывать:

- **В дереве один пункт и полный путь.** Первая версия ставила два (путь от корня и полный) - Макс оставил один.
  Полный путь ведёт к файлу откуда угодно, в том числе из разговора, поднятого вне проекта, а на экране не стоит
  ничего: чип показывает только имя файла.
- **Место - сразу под «Copy Path/Reference…»** (в дереве - внутри `CutCopyPasteGroup`, в окне Commit - прямо в
  `ChangesViewPopupMenu`, оба раза после `CopyReferencePopupGroup`): про путь и тот пункт, и наш, так выбрал Макс. Первой версией пункт стоял над «New» - верх меню жмут по привычке, и
  всё съезжало.

Что легко сломать:

- **Группа буфера обмена общая**: она же стоит в главном меню Edit, в окне структуры, в консоли и в навигационной
  панели. Там пункт прячется сам (`offeredIn`): из меню он показывается только в редакторе, в дереве и в окне
  Commit (`OFFERING_MENUS`), а сочетание клавиш и Search Everywhere работают везде, где есть файл. Тест держит
  список мест. Новое меню для пункта - это `add-to-group`, `override-text` и строка в `OFFERING_MENUS`: без
  последней пункт встанет на место и тут же спрячется.
- **Id `AmazingClaudeCode.SendSelectionAbsolute` не переименовывать**, хотя класс давно другой и служит обоим
  меню: под этим id лежат сочетания клавиш в чужих keymap, новое имя молча их отберёт.
- **В редакторе файл берётся только из `VIRTUAL_FILE`** (`chosenFiles`). Список файлов платформа выводит и
  там, но из чего попало в контексте, включая элемент под кареткой, - и он может назвать файл, на который ведёт
  ссылка, а не открытый. В дереве - `VIRTUAL_FILE_ARRAY`.
- **Не с локального диска - не предлагается**: запись внутри jar в «External Libraries», файл в памяти. Пункт
  на таком узле скрыт, из смешанного выбора такое выпадает. Временная ФС тестов считается локальной, поэтому
  тест берёт `LightVirtualFile`.
- Чипы приходят тем же `picked`, что и из скрепки и перетаскивания (`ClaudePanel.attachFiles`), без похода на
  диск - файлы уже в памяти IDE. Использование считается фичей `send_path` (только ACC, пока форк Codex её не
  получил - см. `features.test.ts`).
- **Место в меню тестом не проверить**: платформенный тест не грузит `plugin.xml` плагина, его действий там
  нет вовсе. `SendAbsolutePathActionTest` держит, какие файлы берутся и в каких местах пункт виден.
  Расстановку смотреть в песочнице: правый клик по файлу, по папке, по нескольким сразу, по узлу «External
  Libraries». Путь в чипе не виден - его ловят перехватом `window.__accReceive` через CDP (сообщение `picked`).
